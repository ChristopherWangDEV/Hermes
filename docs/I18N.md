# 文案与语言包

> 状态：**设计已定，迁移进行中**（第 1 批已改，剩 45 处）。

## 为什么换成语言包

现在的写法是 `tr("unknown argument %q", "未知参数 %q")`：两种语言写在调用点旁边。
它有两个问题：

1. **文案散落在代码里**，译者要读 Go 源码才能改字；
2. **没有任何东西能证明两种语言是成套的** —— 漏一句不会红，只会让界面慢慢分裂。

伙伴项目 **Lexii** 是逐条校准语言包的工作台，它的 `.rp` 格式一份文件装
「全部键 + 每种语言的译文 + 每条的状态（draft / reviewed / flagged）」。
Hermes 把文案导进 `.rp`，用 Lexii 校准，再导回来。

## 键就是英文原文

```
tr("unknown argument %q")        // ← 英文原文即键
```

`i18n/hermes.rp` 里：

```json
{"key":"unknown argument %q","source":"unknown argument %q",
 "translations":{"zh-Hans":"未知参数 %q"},"state":"reviewed"}
```

好处：

- 调用点仍然**可读**：读代码的人看到的就是那句话，不需要去查键；
- **缺译会退化到英文**，而不是显示一个键名；
- 新增文案时不用先想键名（想键名是另一种形式的翻译工作）。

## 目录与加载

```
i18n/hermes.rp          ← 唯一语言包（go:embed 进二进制）
```

`tr(en)` 的行为：

| 环境 | 结果 |
|---|---|
| 默认（无 `HERMES_LANG`） | 英文原文 |
| `HERMES_LANG=zh` | 查表；**查不到就回退英文** |
| `HERMES_LANG=zh` 且 `--verbose` | 回退时打一行 `missing translation: <en>` |

最后一行是刻意的：静默回退会让"漏译"永远发现不了。

## 三个命令

```sh
hermes i18n export --rp i18n/hermes.rp   # 从代码提取键，写出 .rp（给 Lexii）
hermes i18n import i18n/hermes.rp         # 从 .rp 回写（编译期 embed，不需要运行时读）
hermes i18n check                         # CI 用：缺译 / 多余键 / 空译 → 非零退出
```

`check` 是守卫的实体：它让"两种语言不成套"变成一条会红的检查。

## 与 Lexii 的边界

Lexii 只管**校准**，不参与构建。构建只依赖仓库里的 `i18n/hermes.rp`，
所以 CI 不需要装 Swift 工具链，也不需要联网。
